# Извлечение кандидатов в классы из сценариев

| Существительное из сценария | Решение | Почему |
|---|---|---|
| клиент | **класс** | есть идентичность, история поездок, жизненный цикл |
| номер телефона | атрибут Клиент.телефон | нет собственного поведения, просто идентификатор |
| автомобиль | **класс** | физический объект с состоянием (свободен/в аренде/на обслуживании) и историей |
| бортовой модуль | не моделируем как класс предметной области | это внешняя система (актёр), а не часть доменной модели |
| бронь | **класс** | своё состояние (активна/отменена/истекла) и жизненный цикл, отдельный от аренды |
| аренда | **класс** | есть начало, конец, пробег — состояние, которое меняется во времени |
| зона завершения аренды | **класс** | имеет название и геометрию, участвует в проверке при завершении |
| координаты (GPS) | не моделируем отдельным классом | атрибут-снимок момента, используется зоной и автомобилем, не имеет собственного жизненного цикла |
| тариф / стоимость минуты | **класс** (абстрактное правило тарификации) | правило меняется, есть варианты (поминутный, пакетный) — типичный кандидат на абстрактный класс |
| стоимость поездки | атрибут/производное значение Аренда.рассчитатьСтоимость() | вычисляется по правилу тарификации, не хранится как отдельная сущность |
| штраф | **класс** | есть сумма, причина, собственная идентичность, отдельная от аренды запись для истории |
| причина штрафа | enum ПричинаШтрафа | фиксированный список значений, не полноценный класс |
| способ оплаты | **интерфейс** СпособОплаты | клиент платит либо картой, либо бонусами — общий контракт списания |
| карта оплаты | **класс**, реализует СпособОплаты | хранит данные карты, специфична для платёжного шлюза |
| бонусный счёт | **класс**, реализует СпособОплаты | внутренний баланс клиента, не требует внешнего шлюза |
| чек / уведомление | не моделируем | артефакт представления клиенту, вне предметной области (как «памятка» в примере с библиотекой) |
| статус аренды/брони/авто | enum (СтатусАренды, СтатусБрони, СостояниеАвто) | фиксированный набор состояний; СтатусАренды добавлен в ПР2 по диаграмме конечного автомата |

Работа выполнена по классическому приёму: из `scenarios.md` (часть 2) выписаны
все существительные, и для каждого решено — класс, атрибут, перечисление или
не моделируем вовсе.
