# ADR-0003. Попадание в зону завершения проверяется на сервере средствами PostGIS

**Дата:** 2026-10-26
**Статус:** принято
**Область:** выбор технологии (`ЗонаЗавершения.содержит()`, ВИ-06)

## Контекст

При завершении аренды (ВИ-05) система решает, стоит ли автомобиль в зоне
завершения. От ответа зависит штраф 3000 ₽ и вызов эвакуатора, так что ошибка
стоит денег и жалоб. Требование из `traceability.md`: точность не хуже 10 м.
Зоны — многоугольники на карте города, их десятки и они меняются (решение Р-2:
зону можно убрать с карты).

## Рассмотренные варианты

1. **Проверка в мобильном приложении по GPS телефона.** Плюсы: мгновенный
   ответ, нет нагрузки на сервер. Минусы: координаты телефона, а не
   автомобиля (клиент мог отойти); приложение легко подделать, а от ответа
   зависит штраф; зоны пришлось бы синхронизировать на каждый телефон.
2. **Проверка на сервере в коде (библиотека JTS в памяти Backend API).**
   Плюсы: координаты берутся от бортового модуля, ответ доверенный. Минусы:
   полигоны нужно держать в памяти каждого экземпляра API и инвалидировать
   при изменении зон; поиск «ближайшей зоны» для подсказки клиенту пришлось
   бы писать самим.
3. **Проверка в БД: PostgreSQL + PostGIS, запрос `ST_Contains` по
   пространственному индексу.** Плюсы: координаты от бортового модуля;
   полигоны живут там же, где остальные данные, и меняются транзакционно;
   «ближайшая зона» — стандартный запрос `ST_Distance` с сортировкой по индексу.
   Минусы: зависимость от расширения PostGIS (оно должно поддерживаться
   управляемой БД провайдера); геологика частично уходит из доменного
   класса в SQL.

## Решение

Вариант 3. Вариант 1 отвергнут из соображений доверия: штраф нельзя
начислять по данным, которые формирует клиентское устройство. Между 2 и 3
выбран 3, потому что изменение зон — частая операция, а держать
согласованный кэш полигонов в нескольких экземплярах API сложнее, чем
один пространственный индекс.

## Последствия

**Плюсы:** одно место правды для зон; подсказка «ближайшая зона — 300 м» не
требует отдельного кода.
**Минусы:** операция `ЗонаЗавершения.содержит()` в коде — тонкая обёртка над
запросом в `Repositories` (Hibernate Spatial); юнит-тесты геологики требуют
БД (Testcontainers).
**Что станет неверным, если решение пересмотреть:** C4 Container (технология
«PostgreSQL 16 + PostGIS»), Component (`Repositories`, `FleetService`),
Dynamic (шаг 5), диаграмма развёртывания.
