# ADR-0001. Жизненный цикл аренды хранится явным статусом, а не выводится из полей

**Дата:** 2026-10-26
**Статус:** принято
**Область:** модель предметной области (`docs/02-domain/domain.puml`)

## Контекст

В ПР1 у класса `Аренда` не было статуса: «идёт ли поездка» вычислялось по полю
`конец` (`null` — идёт, не `null` — закончена). Автомат ПР2 показал, что
у аренды 7 состояний верхнего уровня, и часть из них по полям не различить:
«Ожидает оплаты» и «Задолженность» имеют одинаковые `конец ≠ null` и
одинаковую сумму, отличаясь только исходом списания. «На проверке» отличается
от «Завершается» лишь тем, что истекли 30 секунд без координат.

От состояния зависит, что разрешено: кнопка «Продолжить поездку» доступна
только в «Завершается», новые брони клиента блокируются в «Задолженности»,
обработчик событий повторяет списание только для «Задолженности».

## Рассмотренные варианты

1. **Вычислять состояние по полям.** Добавить поля `оплачено : boolean`,
   `ожидаетОператора : boolean`, `аннулирована : boolean` и выводить состояние
   функцией. Плюсы: нет поля, которое может разойтись с данными. Минусы: 2⁴
   комбинаций флагов, из которых осмысленны 7, остальные — невозможные
   состояния, которые придётся запрещать проверками. Переходы автомата
   размазаны по коду, менявшему отдельные флаги.
2. **Явное поле `статус : СтатусАренды` (enum), меняется только операциями
   класса `Аренда`.** Плюсы: значения enum один к одному совпадают с состояниями
   автомата, недопустимые комбинации невыразимы, переходы проверяются в одном
   месте (`завершить()`, `продолжить()`, `закрыть()`...). Запрос «все долги»
   — простой индекс по одному столбцу. Минусы: поле может разойтись с другими
   данными, если кто-то поменяет его в обход операций.

## Решение

Вариант 2. Статус меняется только операциями `Аренда`, которые проверяют, что
переход разрешён автоматом из `docs/05-state/lifecycle.puml`; прямой записи в
поле из сервисов нет (модификатор `-` на диаграмме классов).

## Последствия

**Плюсы:** автомат стал исполняемой спецификацией: таблица переходов
`transitions.md` переносится в код почти дословно. Обработчик событий выбирает
задолженности одним запросом.
**Минусы:** при добавлении состояния нужно менять enum, автомат и миграцию
БД одновременно; появилось правило «никто, кроме `Аренда`, не пишет `статус`»,
которое надо контролировать на ревью.
**Что станет неверным, если решение пересмотреть:** `domain.puml` (enum
`СтатусАренды`), `lifecycle.puml` и `transitions.md`, поток объектов
`object-flow.puml`, аудит пункт 4.
