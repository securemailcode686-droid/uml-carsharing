# Актёры и их цели

| Актёр | Кто это | Первичный? | Зачем приходит в систему |
|---|---|---|---|
| Клиент | зарегистрированный водитель с приложением | да | найти, забронировать и арендовать автомобиль, доехать и оплатить поездку |
| Оператор поддержки | сотрудник службы поддержки сервиса | да | разбирать спорные штрафы, помогать с отменой брони, решать технические проблемы |
| Платёжный шлюз | внешняя система обработки платежей (эквайринг) | нет | списывает деньги с карты клиента и возвращает статус транзакции |
| Бортовой модуль | внешняя телематическая система в автомобиле (GPS + управление замками) | нет | получает команды разблокировки/блокировки и передаёт координаты и пробег |
| SMS-шлюз | внешний сервис доставки SMS | нет | доставляет клиенту одноразовый код входа (ВИ-11) |

Первичный актёр — тот, ради чьей цели существует ВИ. Вторичный — тот, кого
система привлекает, чтобы цель достичь. Минимум 3 актёра, из них минимум один —
внешняя система: условие выполнено трижды (платёжный шлюз, бортовой модуль, SMS-шлюз).

*Изменено в ПР3: SMS-шлюз добавлен по итогам аудита согласованности (пункт 1) —
он появился на C4 Context, потому что ВИ-11 и `traceability.md` требуют входа
по SMS-коду, а в списке актёров его не было. Название «Бортовой модуль
автомобиля» сокращено до «Бортовой модуль», как на всех остальных диаграммах
(пункт 9).*
